# T-0004 — P2: Đóng gói spike thành web service để đo trên Render free

- Phase: P2 · Vòng: 3/3 · Ngày: 2026-11-01 · Branch: `task/T-0004` (đã checkout sẵn; không commit, không đổi branch)
- Mục tiêu (một câu): cho image `spike/p2` chạy được như Render free web service (lắng nghe `$PORT`), cung cấp endpoint có secret để chạy bộ ca/bench và báo khả năng cách ly của môi trường, kèm script client đo cold start từ bên ngoài.
- Context files (chỉ đọc): `spike/p2/**`, `reports/P2_spike.md`, `PROJECT_PLAN.md` mục 3.3 và 9/P2 (tiêu chí 5, 6, 7).
- Allowed files (được tạo/sửa): `spike/p2/**`, `reports/P2_spike.md` (chỉ thêm mục "Render"), `handoff/reports/T-0004.md`.
- Yêu cầu:
  1. `spike/p2/server.mjs` (chỉ thư viện chuẩn Node): lắng nghe `0.0.0.0:$PORT` (mặc định 10000).
     - `GET /health` → 200 `{status:"ok", uptimeMs}` (không cần secret).
     - Các endpoint dưới đây bắt buộc header `X-Spike-Secret` khớp env `SPIKE_SECRET` (so sánh thời gian hằng `crypto.timingSafeEqual`); thiếu/sai → 401; nếu env `SPIKE_SECRET` rỗng/không đặt → mọi endpoint có secret trả 503 (không bao giờ mở).
     - `GET /env-probe` → JSON: `uname -a`, số CPU (`os.cpus().length`), tổng RAM, giới hạn bộ nhớ cgroup (đọc `/sys/fs/cgroup/memory.max` hoặc v1 tương đương, nếu có), uid/gid tiến trình, trường `Seccomp`/`NoNewPrivs`/`CapEff` trong `/proc/self/status`, kết quả thử nhanh launcher: chạy một chương trình nhỏ trong sandbox để xác nhận `setuid`, `setrlimit`, `seccomp_load` thành công (báo từng mục ok/lỗi + errno).
     - `POST /run-suite` → chạy `node run-suite.mjs` (tiến trình con), trả `{exitCode, durationMs, passed, failed, outputTail}` (outputTail ≤ 64 KB).
     - `POST /bench` → chạy `node bench.mjs`, trả `{exitCode, durationMs, outputTail}`.
     - Khóa: chỉ 1 lần chạy suite/bench cùng lúc (409 nếu đang chạy); timeout cứng 5 phút cho mỗi lần.
     - Không có endpoint nào nhận code/đường dẫn/lệnh từ client.
  2. `Dockerfile`: `CMD` mặc định chạy `server.mjs`; `node run-suite.mjs` và `node bench.mjs` vẫn chạy được như trước; `EXPOSE 10000`.
  3. `spike/p2/server-selftest.mjs`: khởi chạy server trên cổng ngẫu nhiên trong cùng container với `SPIKE_SECRET` tạm, kiểm: `/health` 200; `/env-probe` không secret → 401, sai secret → 401, đúng → 200 và có các trường trên; khi không đặt `SPIKE_SECRET` → 503; `/run-suite` đúng secret → exitCode 0 và failed 0; gọi đồng thời 2 lần → một lần 409; `/bench` → exitCode 0. Exit 0 khi và chỉ khi tất cả đúng.
  4. `spike/p2/remote-check.mjs <baseUrl>` (đọc secret từ env `SPIKE_SECRET`): đo thời gian `GET /health` đầu tiên (cold start, ghi rõ là tính từ lúc gửi request), sau đó gọi `/env-probe`, `/run-suite`, `/bench` và in JSON tóm tắt; `--health-only` chỉ đo health.
  5. Không ghi secret thật vào file nào; trong test chỉ dùng secret sinh ngẫu nhiên.
- Môi trường: host không có node; chạy trong Docker. Không chạy lệnh dò. Lệnh shell được phép: các lệnh kiểm chứng dưới đây + `git status/diff/rev-parse`. Khi gọi lệnh docker, đặt `WaitMsBeforeAsync` = 600000 (chờ đồng bộ, không chạy nền).

  - `docker run --rm cppdsa-spike node run-suite.mjs`
  - `docker run --rm cppdsa-spike node server-selftest.mjs`

Trên Render free thật (service `cppdsa-spike`, Singapore): `/env-probe` OK (uid 0, CapEff 0x400cb, NoNewPrivs=1, cgroup memory 512 MiB, setuid/setrlimit/seccomp_load ok; Render metrics: cpu_limit 0.15 CPU). Hai lỗi:
  1. `/bench` → `execve failed: Resource temporarily unavailable` (status 127) ngay lần 1: RLIMIT_NPROC của uid sandbox 10001 bị vượt ngay trên Render (nghi số tiến trình theo uid tính chung ngoài container). Sửa: uid/gid sandbox cấu hình qua env `SANDBOX_UID` (mặc định 2000000000, tạo user/group tương ứng trong Dockerfile; runner, launcher, quyền thư mục, quét /proc dùng giá trị này). Thêm vào `/env-probe`: số tiến trình hiện có của uid sandbox (đếm qua /proc trong container) và kết quả thử fork 5 tiến trình con dưới uid sandbox với NPROC hiện dùng.
  2. `/run-suite` làm container bị OOM-kill (Render event `oomKilled memoryLimit 512Mi`) → server chết. Sửa: thêm env `SPIKE_MEMORY_BUDGET_MB` (mặc định 384); runner đọc giới hạn cgroup (`/sys/fs/cgroup/memory.max`) và với ca nào có `memoryLimitBytes × (số tiến trình tối đa của ca)` vượt budget thì giảm ML/NPROC của ca cho vừa (ghi rõ trong output), sao cho tổng bộ nhớ con không thể vượt budget (vd NPROC × RLIMIT_AS ≤ budget, hoặc NPROC=1 cho ca MLE). Bộ ca vẫn phải 38/38 PASS local và không OOM khi chạy trong `docker run --memory 512m`.
  3. `bench.mjs`: thêm in `nproc`, `os.cpus().length` và thời gian CPU (user+sys) của mỗi lần chạy bên cạnh wall time, để so sánh CPU throttle 0.15.
